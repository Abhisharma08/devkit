# Privacy policy

Effective November 24, 2026.

DevKit is a free, open-source developer toolbox. All tool processing takes place locally in your browser. The project has no backend, external database, authentication, analytics, advertising, or paid API.

## Tool data

Inputs and outputs stay in memory. DevKit does not save them to local or session storage, transmit them, or keep an input history. Switching tools, closing a popup, or reloading discards the active workspace. Content that you copy enters the system clipboard; operating systems, clipboard managers, or other applications may retain it. Browser extensions or software installed on your device may have their own access to browser content.

## Preferences

Only theme and favorite tool identifiers are stored in local storage. These values remain on the current browser profile and origin. Clear the app's site/extension data to remove them. Preferences are not synchronized to an account or external service.

## Hosting

Opening the website requests its pages and static assets from its host. Hosting infrastructure may process IP addresses and access logs under its own policies. Tool content is not included in these requests. The installed production extension includes its code and assets and can operate offline.

## Browser permissions

The Chrome extension requests only `sidePanel` to provide its native side panel. It does not request access to websites, browsing history, cookies, page contents, or sensitive tab data. Clipboard operations happen only after the user presses Copy. No broad clipboard permission is requested.

## Donations

Donation links are hidden until the maintainer configures a valid HTTPS Buy Me a Coffee profile. Clicking one opens that service, whose policies apply there. No third-party donation scripts, embedded widgets, tracking pixels, or automatic requests are used. Donations do not change access to features.

## Changes and questions

Future changes to data handling must update this policy and be reviewed in the public source. For privacy issues, use the repository's private vulnerability reporting facility as described in SECURITY.md. Maintainers should publish a support contact and the final privacy-policy URL when creating a deployment or store listing.
